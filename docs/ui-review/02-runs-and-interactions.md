# Запуски, деталь запуска, «Нужен ответ»

> **Состояние «до»: 8 сентября 2026.** Описанные здесь экраны и адреса заменены переносом
> панели на дерево `/agentiz` — читайте это как исходные данные того решения, а не как описание
> нынешней панели. Как она устроена сейчас — [`../guides/panel-ui.md`](../guides/panel-ui.md).

## `/dashboard/agentiz-runs` — лента запусков (`AgentizRuns.tsx`, 214 строк)

![Лента запусков](screenshots/agentiz-runs.png)

Самообновляющаяся лента (`Что идёт прямо сейчас — обновляется каждая 3 секунды`, `listRuns`
поллится таймером) в двух блоках: **«Идёт сейчас»** (статус `pending`/`working`, с кнопкой
`Отменить` → `cancelRun`) и **«Завершились недавно»** (`succeeded`/`failed`/…). Каждая строка —
статус-бейдж, заголовок задачи (ссылка, открывает деталь этого же запуска через `?runId=`),
проект, `trigger` (`manual`/…), воркер, время, список стадий бейджами (`0. investigate`,
`1. decide`, …) и однострочное резюме (`resultSummary`). Если у задачи есть ожидающий ответа
`AgentRunInteraction`, строка получает оранжевую пилюлю-ссылку на `/dashboard/agentiz-interactions`
(`AgentizRuns.tsx:105`). В шапке — два постоянных ярлыка `Нужен ответ` / `Задачи`.

Если открыть с `?runId=<id>`, `runRoutes.ts:261` подменяет `moduleComponent` на `AgentizRunDetail`
вместо `AgentizRuns` — то есть **это два разных React-компонента за одним URL**, различённые
только query-параметром на сервере (см. `layers/app-agentiz/lib/runRoutes.ts:261`).

## Деталь запуска — `AgentizRunDetail.tsx` (766 строк)

![Деталь запуска](screenshots/agentiz-runs-detail.png)

Сверху вниз, каждый блок — своя `rounded-lg border p-4` карточка:

1. **Шапка**: статус-бейдж, `trigger`, дата; ссылка `настроить →` на пайплайн, из которого запуск
   создан (`agentiz-pipelines?projectId=...&specId=...`); кнопка `Отменить запуск`, пока запуск
   активен.
2. **«Проверка workspace-изменений»** — появляется только когда у запуска есть
   `AgentWorkspaceProposal` (пайплайн с `source: worker_workspace`, см. `AGENTS.md`). Показывает
   путь воркспейса, базовую ветку/sha, `tree sha`, историю ревизий (`#1: N файлов`, `#2: …`), и
   набор кнопок **в зависимости от статуса**:
   - `waiting_review` — поля «Ветка» (заблокировано, если `targetMode === "current"`) и «Commit
     message», кнопка `Подтвердить commit и push` (заблокирована без сообщения коммита или если
     дифф обрезан), текстовое поле замечаний + `Продолжить работу` (отправляет ревью-комментарий
     агенту без коммита — `continueWorkspaceProposal`), и `Отклонить и вернуть workspace` (красная
     рамка).
   - `push_failed` — `Повторить push` / `Вернуть workspace`.
   - `reset_failed` — только `Повторить безопасный reset`.
   - Если что-то потеряно не будет — при отклонении есть заметка о `stashSha`/`abandonedRef`
     («работа не потеряна, лежит в `git stash apply ...`») — это то же поведение, что описано в
     `AGENTS.md` про `workspace_reset`/стеш.
   Это ровно тот самый экран ручного review, в паре с MCP-инструментами `agentiz.proposals` /
   `agentiz.manageProposal`, описанными в `AGENTS.md` (раздел «workspace still held by an earlier
   proposal»).
3. **«Вопросы агенту»** — список `AgentRunInteraction`. Каждый ожидающий (`pending`, персиковая
   рамка) рендерит **форму по JSON Schema** запроса (`interaction.requestedSchema` —
   `humanInputSchema.ts`): текстовые/числовые поля, чекбоксы, `<select>` для перечислений
   (`humanInputChoices`), обязательные помечены `*`; три действия — `Ответить`, `Отказаться`,
   `Отменить запрос`. Отвеченные показывают, что было отправлено, кем и когда (плюс
   `доставлен <дата>`, если событие уже дошло агенту).
4. **«Стадии»** — список `AgentStageExecution` со статус-бейджами, номером/ролью, временем начала
   и конца.
5. **«Логи»** — тёмный (`bg-slate-900`-подобный) моноширинный блок, каждая строка окрашена по
   уровню (`LOG_LEVEL_COLORS`) — тот самый `listRunLogs` (`AGENTS.md`: единая точка чтения логов
   для панели/мобилки/`agentiz.runDetails`), с постраничной подгрузкой (это read side «первая
   страница — хвост», см. `AGENTS.md`).
6. **«Дифф»** — если запуск ничего не менял, одна строка текста; иначе сводка (файлов/+/−, откуда
   sha, применено ли), список операций одной строкой на файл (глиф `−`/`→`/`~` — `delete` /
   `rename` / прочее), предупреждение о `truncated`, сам патч через `<DiffViewer>` (см. ниже), и
   кнопка `Применить в репозиторий` — **только** пока нет активного `proposal` и дифф ещё не
   применён (иначе кнопки нет вовсе — «кнопка, которая всегда падает, хуже отсутствия кнопки»,
   комментарий в исходнике на `AgentizRunDetail.tsx` перед этим условием).

### `components/diff-viewer.tsx` (523 строки)

Свой рендерер unified diff (не сторонняя библиотека) с переключателем режима «unified/split»,
persist-нутым в `localStorage` под ключом, который передаёт вызывающий компонент
(`persistKey="agentiz.diffViewMode"`), подсветкой добавленных/удалённых строк и (судя по размеру
файла) операциями `rename`/`delete` со своим представлением. Единственное переиспользуемое UI
за пределами Adminizer-примитивов во всей ревизии — стоит вынести как отдельный кирпичик при
переразбивке, а не копировать его подход (сырые классы, ручная разметка diff) на остальные экраны.

## `/dashboard/agentiz-interactions` — «Нужен ответ» (`AgentizInteractions.tsx`, 157 строк)

![Нужен ответ](screenshots/agentiz-interactions.png)

Сквозной инбокс: список **всех** ожидающих `AgentRunInteraction` по доступным пользователю
проектам (`listPending`), независимо от задачи/запуска — то есть то же самое, что «Вопросы
агенту» внутри `AgentizRunDetail`, но собранное поперёк всех запусков. Каждая строка — ссылка
`открыть запуск` (`agentiz-runs?runId=...`) плюс те же три кнопки `Ответить`/`Отказаться`/
`Отменить запрос`. Форма ответа по схеме **не продублирована** отдельным компонентом — это
буквально тот же JSX-паттерн, скопированный из `AgentizRunDetail.tsx` (сравните оба файла: те же
имена полей, тот же порядок кнопок) — кандидат на общий компонент при переразбивке, а не два
места, которые надо чинить синхронно при следующем изменении формата `requestedSchema`.

Пустое состояние (как на скриншоте — «Сейчас ни один агент не ждёт ответа») — единственный текст
на всю страницу, без иллюстрации/подсказки, что делать дальше.
