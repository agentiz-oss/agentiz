# `/dashboard/workflows` и `/dashboard/workflow` — канвас движка

> **Состояние «до»: 8 сентября 2026.** Описанные здесь экраны и адреса заменены переносом
> панели на дерево `/agentiz` — читайте это как исходные данные того решения, а не как описание
> нынешней панели. Как она устроена сейчас — [`../guides/panel-ui.md`](../guides/panel-ui.md).

Это не код app-agentiz: оба модуля (`WorkflowList`, `WorkflowEditor`) собираются из
`node_modules/@nodeknit/app-workflow/adminizer/modules/*` — отдельного пакета/сабмодуля
(`app-workflow-skeleton` в памяти проекта). app-agentiz участвует только как **поставщик узлов**
(`agentiz.task.trigger` / `.match` / `.run`, `agentiz.pipeline`, `agentiz.approval`, …) через
type-only коллекцию `workflowNodes` (см. `AGENTS.md`) — сама раскладка канваса к app-agentiz
отношения не имеет, но она — часть того, что видит пользователь Agentiz, поэтому здесь тоже
описана.

## `/dashboard/workflows` — список (`WorkflowList`)

![Список воркфлоу](screenshots/workflows-list.png)

Заголовок «Воркфлоу», кнопки `+ Новый воркфлоу` и `Обновить`. Пустое состояние объясняет
архитектуру прямо в тексте: «Источники графов подключаются коллекцией `workflowSpecProviders`;
если кнопки создания нет — ни один слой их не поставляет» — то есть сама кнопка создания скрывается,
если ни один установленный слой не зарегистрировал провайдера графов (в этой инсталляции app-agentiz
его регистрирует, кнопка есть).

Открыт с `?model=AgentProject&entityId=<id>` (так на него ссылается карточка «Воркфлоу» на хабе
проекта, `01-project-hub-and-tasks.md`) — список в этом случае должен фильтроваться по графам,
привязанным к этой сущности; в текущей инсталляции графов не было заведено, поэтому фильтрация не
проверена вживую.

## `/dashboard/workflow?providerId=...&specId=...` — редактор графа (`WorkflowEditor`)

![Канвас воркфлоу](screenshots/workflow-canvas.png)

React Flow (`@xyflow/react`) в три колонки:

- **Слева — «Палитра»**: поиск ноды + список узлов, сгруппированный по поставщику (здесь — один
  раздел `AGENTIZ` с 9 узлами: `Задача Agentiz` [триггер], `Проверка задачи`, `Запустить
  пайплайн...`, `Пайплайн (с ожид...)`, `Статус задачи (текст)`, `Комментарий в зад...`, `Решение
  человека`, `Сколько накопилос...`, `Создать задачу`). Подпись под списком: «Перетащите ноду на
  холст или кликните, чтобы добавить. Delete — удалить выбранное. Кнопка ▷ на триггере запускает
  его вручную, уже развёрнутым» — то есть ручной тест-прогон графа встроен прямо в канвас, без
  отдельного экрана запуска.
- **Центр — сам холст**: точечная сетка, зум +/− и «развернуть на весь экран» в правом нижнем
  углу; в шапке холста — название графа (редактируемое поле «Новый воркфлоу»), тумблер `активно`,
  индикатор валидности графа («граф корректен» — зелёным, судя по цвету рамки бейджа), undo/redo
  стрелками, кнопка `Развернуть` (вероятно — открыть граф на весь экран/полноэкранный режим
  редактирования), иконка настроек (шестерёнка) и иконка сворачивания правой панели.
- **Справа — панель свойств узла**: пусто, пока ничего не выбрано («Выберите ноду на холсте, чтобы
  настроить её»).

Важное архитектурное ограничение с прямым UI-следствием (см. `AGENTS.md`, «fan-in allowed, fan-out
forbidden»): у одной ноды может быть несколько **входящих** связей, но не несколько исходящих из
одного порта — редактор обязан это валидировать на холсте (это и есть «граф корректен»/некорректен
в шапке), иначе тихо потеряется часть веток при исполнении.

Для переразбивки Agentiz-интерфейсов важно понимать: **этот экран не в юрисдикции app-agentiz** —
его форма/раскладка меняется через пакет `@nodeknit/app-workflow`, публикуемый отдельно (см.
`AGENTS.md`: «app-adminizer — отдельный пакет», то же верно и для app-workflow). Переразбивка
собственных экранов Agentiz может **добавлять** новые узлы и переиспользовать канвас как есть, но
не должна пытаться перекроить сам редактор в рамках работы над `layers/app-agentiz`.
