# Репозитории, GitHub/GitLab-интеграции

> **Состояние «до»: 8 сентября 2026.** Описанные здесь экраны и адреса заменены переносом
> панели на дерево `/agentiz` — читайте это как исходные данные того решения, а не как описание
> нынешней панели. Как она устроена сейчас — [`../guides/panel-ui.md`](../guides/panel-ui.md).

Три экрана, которые вместе покрывают одну сущность (`AgentGitConnection`/`AgentRepository`/
`AgentProjectRepository` — core-модели, см. `AGENTS.md`: репозитории — core-концепция, провайдер
даёт только диалект OAuth), но живут в разных слоях и не ссылаются друг на друга напрямую, кроме
текстовых подсказок.

## `/dashboard/agentiz-repos` (`AgentizRepositories.tsx`, 479 строк)

![Репозитории](screenshots/agentiz-repos.png)

Два блока:

1. **«Подключения»** — список `AgentGitConnection` (аккаунты, авторизованные через OAuth), кнопки
   `Подключить GitHub` / `Подключить GitLab` ведут на `agentiz-github`/`agentiz-gitlab`
   (`item.route` из `providerPages()` — список провайдеров генерируется динамически из
   `listGitConnectionProviders()`, так что третий провайдер добавится сюда без правки этого файла).
   Если подключений нет — подсказка «Начните с OAuth-приложения на странице провайдера». Если
   есть — под каждым подключением, судя по коду, кнопка `Синхронизировать репозитории`.
2. **«Репозитории проекта»** — привязка `AgentRepository` к текущему проекту:
   `<select>` (выбрать репозиторий из уже засинканных) + `Добавить репозиторий`, либо
   `showPicker`-тумблер `Отмена`/показать список для выбора. Пустое состояние — «У проекта пока
   нет привязанных репозиториев».

## `/dashboard/agentiz-github` (`layers/app-agentiz-github-integration/adminizer/modules/AgentizGithub.tsx`)

![GitHub-интеграция](screenshots/agentiz-github.png)

Комментарий в самом файле называет объём страницы: «The whole GitHub-specific screen: the OAuth
application and the button that starts the flow» — то есть это осознанно узкий экран. Один блок
«OAuth-приложения»: `Синхронизировать репозитории`, `Добавить приложение` (раскрывает форму
Client ID/secret), список уже добавленных приложений с действиями (вероятно
редактировать/удалить/переавторизовать, судя по трём кнопкам на строку в коде). Пустое состояние
прямо перечисляет шаги: «Создайте OAuth App в GitHub (Settings → Developer settings → OAuth Apps)
и перенесите сюда Client ID и secret».

## `/dashboard/agentiz-gitlab` (`layers/app-agentiz-gitlab-integration/adminizer/modules/AgentizGitlab.tsx`)

![GitLab-интеграция](screenshots/agentiz-gitlab.png)

Пиксель-в-пиксель то же самое, что GitHub-экран, с другими словами («Application» вместо «OAuth
App», путь в UI GitLab другой) — два отдельных файла в двух отдельных слоях
(`app-agentiz-github-integration` / `app-agentiz-gitlab-integration`), а не один компонент с
пропом-конфигом провайдера. Учитывая, что `AgentizRepositories.tsx` уже вычисляет список
провайдеров динамически (`providerPages()`), а эти два экрана структурно идентичны — явный
кандидат на слияние в один параметризуемый компонент при переразбивке, при условии, что каждый
провайдерский слой сможет по-прежнему не тянуть чужой (иначе нарушится изоляция слоёв, о которой
явно говорит `AGENTS.md`: «gitProviders» — это провайдерский диалект, а не core).

Важно: **в боковом меню виден только пункт «GitLab-интеграции»** — «GitHub-интеграции» там нет
(см. `00-overview.md`, дерево меню) при том что оба модуля собираются и оба доступны по прямому
URL. Несогласованность самого меню, не прав доступа — стоит проверить перед переразбивкой, баг
это или сознательный выбор (git-история модуля может подсказать).
