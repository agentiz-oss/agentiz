# `/dashboard/agentiz-workers` — воркеры и harness-лимиты

> **Состояние «до»: 8 сентября 2026.** Описанные здесь экраны и адреса заменены переносом
> панели на дерево `/agentiz` — читайте это как исходные данные того решения, а не как описание
> нынешней панели. Как она устроена сейчас — [`../guides/panel-ui.md`](../guides/panel-ui.md).

`AgentizWorkers.tsx`, 1450 строк — самый большой кастомный модуль. Единственный экран без
привязки к текущему проекту в шапке (воркеры не проектная сущность — доступ к проектам настраивают
внутри карточки воркера).

![Воркеры](screenshots/agentiz-workers.png)

Верх — кнопка `Новый воркер` (поле «Название», опционально; создание выдаёт токен подключения —
подсказка «панель выдаст токен, с которым воркер сразу подключится», плюс ссылка на
`docs.agentiz.m42.cx/worker-install`). Пустой список воркеров показывает эту же подсказку вместо
таблицы.

Каждый воркер — одна большая карточка (то, что на скриншоте — «Local worker (agentiz-local)»):

- Шапка: статус-бейдж (`active`/`paused`/`revoked`), имя, `kind` (`local`/`external`), токен
  (только префикс), онлайн/офлайн + время последнего контакта, взято job'ов, доступ к
  проектам/репозиториям одной строкой.
- Кнопка `Пауза` (переключает `status`) + два `<select>` «Доступ к проектам…» / «Доступ к
  репозиториям…» (`allowedProjectIds`/`allowedRepositoryIds` — пусто = все).
- Поле «Одновременно job'ов» (`maxConcurrentJobs`) + `Сохранить`.
- **«Harness и лимиты»** — привязки harness-ключа (`claude`, …) к `AgentHarnessSubscription`;
  поле «ключ harness'а» + `Добавить привязку`. Текст поясняет, что лимит принадлежит подписке, не
  машине (см. `AGENTS.md`, раздел про `AgentHarnessSubscription`).
- **«Откуда разрешён Git push»** — поле абсолютного пути + `Разрешить push` (`gitPushRoots`);
  текст явно предупреждает, что `/` не принимается и что это доверие к машине, а не к пайплайну.
- **«Готовые папки для пайплайнов»** — ключ + путь + чекбокс `Разрешить Git push` + `Добавить
  папку` (`workspaces[]` — это ровно те записи, на которые ссылается редактор пайплайна,
  `03-pipelines.md`, пункт про `worker_workspace`).
- **«Исполнители для ручного запуска»** — `Добавить Claude` / `Добавить Codex`
  (`manualExecutors`, пресеты `EXECUTOR_PRESETS.claude/codex` — команда ACP фиксированная,
  оператор не может ввести свою произвольную команду через этот UI, только выбрать пресет).
- Внизу карточки — блок capacity/лимитов (`getCapacity`) — вероятно текущее состояние
  `exhaustedUntil`/окон, судя по названию эндпоинта; на этом воркере (offline, без активной
  подписки) блок пуст на скриншоте.

**«Подписки»** (`AgentHarnessSubscription`) — отдельная карточка под списком воркеров: поле
названия + `<select>` провайдера (`anthropic` и т.п.) + `Новая подписка`. Это тот самый объект,
вокруг которого построена вся система лимитов, описанная в `AGENTS.md`
(«Harness limits and queue scheduling») — здесь же, судя по всему, должны быть видны
`exhaustedUntil`/`windows`/`alignReset*`, но эта ревизия смотрела экран без активных лимитов
(пусто) — при следующей ревизии стоит завести воркер с реальным Claude-логином, чтобы увидеть
карточку подписки с данными.

Пять источников данных на одном экране (`getWorkers`, `getCapacity`, `getProjects` с `HOME_URL`,
`getRepositories` с `REPOS_URL`, плюс сам `API_URL` для мутаций) — тот же паттерн «один React-файл
знает про пять чужих роутеров», что и у `AgentizPipelines.tsx` (см. `03-pipelines.md`).
