# Хаб проекта и задачи

> **Состояние «до»: 8 сентября 2026.** Описанные здесь экраны и адреса заменены переносом
> панели на дерево `/agentiz` — читайте это как исходные данные того решения, а не как описание
> нынешней панели. Как она устроена сейчас — [`../guides/panel-ui.md`](../guides/panel-ui.md).

## `/dashboard/agentiz` — хаб проекта (`AgentizHome.tsx`, 273 строки)

![Хаб проекта](screenshots/agentiz-home.png)

Единственная точка входа, где выбирают **проект** (`AgentProject`) — переключатель живёт только
здесь, остальные экраны получают `projectId` через query-параметр, который сюда же и ведёт
обратно (`← к проекту`). Одна страница, без вкладок, сверху вниз:

1. Заголовок + описание (`<h1>`/подзаголовок — общий для всех модулей паттерн, см. `00-overview.md`).
2. **«Проекты»** — карточка-переключатель: список `AgentProject` кнопками (активная — с рамкой),
   под ними `Синхронизировать задачи` (`_method: "syncProject"`, дергает и git-репозиторий, и все
   `AgentTaskSource` проекта разом — см. `AGENTS.md` про `GitSyncService`/`TaskSourceSyncService`)
   и `Последняя синхронизация: <дата|никогда>`.
3. Заголовок текущего проекта, затем **сетка статистики** (`grid gap-3 sm:grid-cols-2
   lg:grid-cols-4`) — 4 карточки: открытых задач, воркеров на связи (`online/total`), запусков
   всего, пайплайнов. Число берётся из `getProjectStats` (агрегаты по `AgentTask`/`AgentRun` +
   `AgentWorkerRegistryService.list()`, см. `layers/app-agentiz/index.ts:283-329`).
4. «Задачи по статусу» — теги-бейджи со счётчиками (та же статистика).
5. Секция «Уведомления» с кнопкой `Настроить` — это врезка `NotificationPolicySection`
   (переиспользуемый компонент, разбор — [`05-members-and-notifications.md`](05-members-and-notifications.md)).
6. **Семь карточек-ссылок** (`NavCard`, `block rounded-lg border p-4 hover:bg-primary/5`) — это и
   есть переходы на все остальные разделы проекта, с заголовком и одной строкой описания:
   `Задачи` → `agentiz-tasks?projectId=...`, `Пайплайны` → `agentiz-pipelines?projectId=...`,
   `Воркфлоу` → `/dashboard/workflows?model=AgentProject&entityId=<id>` (фильтр воркфлоу-канваса по
   этому проекту), `Воркеры` → `agentiz-workers` (**без** `projectId` — воркеры не проектная
   сущность), `Репозитории` → `agentiz-repos?projectId=...`, `Участники` →
   `agentiz-members?projectId=...`, `Уведомления` → `agentiz-notifications` (без `projectId` —
   открывает общие правила, а не проектные).
7. «Последние запуски» — до 8 строк, каждая — ссылка на `agentiz-runs?runId=<id>`, с ссылкой
   `Все задачи и запуски →` в шапке блока.

Все данные — три `axios.get`/`axios.post` на один и тот же `route: '/agentiz'`
(`layers/app-agentiz/index.ts`), различённые полем `_method` в теле/квери (`getProjects`,
`getProjectStats`, `syncProject`, `testConnection`, `updateProjectSecrets`, `syncAll`) — RPC-стиль
поверх одного POST-эндпоинта, не REST.

## `/dashboard/agentiz-tasks` — трекер задач (`AgentizTasks.tsx`, 1500 строк — самый большой модуль)

![Список задач](screenshots/agentiz-tasks.png)

Двухпанельный экран: слева список задач с фильтрами, справа (при выборе) — деталь. Верх:

- Заголовок + три кнопки-переключателя видимости блоков: `Нужен ответ` (переход на
  `agentiz-interactions`, не тумблер), `Новая задача` (тумблер `showNewTask` — раскрывает форму
  создания вручную: заголовок, описание, приоритет, проект), `Источники задач (N)` (тумблер
  `showSources` — список подключённых `AgentTaskSource`/добавление нового трекера).
- Строка из 5 фильтров: проект, статус, приоритет, таск-менеджер, текстовый поиск по заголовку —
  все клиентские `<select>`/`<input>`, значения зависят от ответа `/agentiz-tasks?_method=filters`.
- Список задач — карточки со статус-бейджем (`done`/`new`/…, палитра `STATUS_COLORS`),
  приоритет-бейджем, заголовком, источником (`вручную` или имя трекера), числом комментариев,
  тегами и (если из внешнего трекера) номером `#N` и статусом `трекер: open/closed`.

Деталь задачи (клик по карточке) — самая насыщенная часть файла (~600 строк, `AgentizTasks.tsx:960-1500`):

- Шапка: статус-бейдж + приоритет-бейдж + заголовок, под ней — проект, источник, ссылка «открыть в
  трекере» (если внешняя задача), пометка «(адаптер недоступен)», если источник отключён.
- Строка actions: `<select>` смены статуса, `<select>` смены приоритета (оба меняют сразу,
  `patchTask`), кнопка `Запустить пайплайн` (`runPipeline`, с выбором раннера/модели/уровня
  рассуждений — ручной override, см. `AGENTS.md` про `executorOverride`).
- «Воркфлоу» — если у задачи есть активный `AgentWorkflowRun`, показывает его статус и узел, где
  застрял (относится к «кругу с человеком», см. `docs/guides/workflow-human-gate.md`).
- «Обсуждение» — лента `AgentTaskComment` (человеческие и агентские) + форма добавления
  комментария (эта запись — то, что заводит триггер `agentiz.task.comment` в воркфлоу-движке).
- Прикрепление файлов — форма загрузки (`POST /agentiz-tasks/attachments`, см. `AGENTS.md` про
  `taskAttachments.ts`), список уже прикреплённых.
- «Запуски» — до нескольких последних `AgentRun` этой задачи, каждый кликабелен → деталь запуска.
- «Логи последнего запуска» — встроенный хвост лога прямо в панели задачи, без перехода на экран
  запуска (то же `listRunLogs`, что и на `AgentizRunDetail` — см. `02-runs-and-interactions.md`).

Источники задач (форма добавления, тумблер «Источники задач») перечисляет провайдеров
таск-менеджеров (`taskManagers` collection, см. `AGENTS.md`) и просит их конфиг — вынесенный
JSON-подобный набор полей, зависящий от выбранного провайдера.
