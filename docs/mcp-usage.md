# Использование MCP в Agentiz

## Что это за endpoint

Agentiz публикует каталог серверных инструментов по адресу `/mcp`. Через него можно читать
состояние проектов, задач, запусков и воркеров, а также явно выполнять административные действия.

Текущая реализация `app-mcp` использует собственный REST/JSON-контракт с версией `1.1`:

| Метод | Путь | Назначение |
| --- | --- | --- |
| `GET` | `/mcp` | Компактный каталог групп и инструментов |
| `GET` | `/mcp/group/:group` | Полные описания и JSON Schema одной группы |
| `GET` | `/mcp?flat=1` | Полный плоский каталог; оставлен для совместимости |
| `POST` | `/mcp/call/:toolName` | Вызов инструмента; параметры передаются JSON-телом |

Несмотря на поле `"protocol": "mcp"`, это не стандартный JSON-RPC/Streamable HTTP transport
Model Context Protocol. Клиент, рассчитанный на официальный MCP transport, нельзя направить на
этот URL без отдельного адаптера.

## Включение и ключи

Сервер монтирует endpoint только при точном значении:

```dotenv
MCP_ENABLED=true
MCP_ADMIN_KEY=<секрет, с которым сервер сравнивает входящие запросы>
```

Назначение переменных различается:

- `MCP_ADMIN_KEY` читает сервер `app-mcp`. Если переменной нет, все `protected`-инструменты
  недоступны.
- `MCP_KEY` — принятое в этом репозитории имя клиентского ключа в локальном `.env`. Сам сервер его
  не читает. В production-развертывании значение из `MCP_KEY` используется для обращения к
  `https://agentiz.m42.cx/mcp`.
- `MCP_HOST` сервер также не читает. Его можно использовать в клиентских scripts, но серверный
  путь сейчас зафиксирован как `/mcp`.

Передавайте ключ заголовком. Query-параметр `?mcp_key=...` поддерживается, но может попасть в
логи, историю браузера и метрики прокси, поэтому годится только для вынужденной совместимости.

```bash
source .env
MCP_URL=https://agentiz.m42.cx/mcp
curl -sS -H "X-Mcp-Key: $MCP_KEY" "$MCP_URL"
```

Для локально запущенного `npm run dev` используйте:

```bash
source .env
MCP_URL=http://127.0.0.1:17280/mcp
curl -sS -H "X-Mcp-Key: $MCP_ADMIN_KEY" "$MCP_URL"
```

Не выводите ключ в консоль и не сохраняйте его в tracked-файлах. В shell-командах заключайте URL
и значение заголовка в кавычки.

## Правильный порядок работы

### 1. Получить компактный каталог

```bash
curl -sS -H "X-Mcp-Key: $MCP_KEY" "$MCP_URL"
```

Поле `info.auth.status` должно быть `authenticated`. Без корректного ключа каталог намеренно
показывает только публичные инструменты. Для развернутого endpoint иногда наблюдался единичный
устаревший ответ `unauthenticated`; повторите тот же запрос один раз, прежде чем проверять ключ.

### 2. Запросить схему только нужной группы

```bash
curl -sS -H "X-Mcp-Key: $MCP_KEY" "$MCP_URL/group/agentiz"
curl -sS -H "X-Mcp-Key: $MCP_KEY" "$MCP_URL/group/agentiz-actions"
```

Используйте `tools[].schema` из ответа как актуальный контракт параметров. Не копируйте схему из
старого примера, если endpoint уже может вернуть текущую.

### 3. Вызвать read-only инструмент

```bash
curl -sS -X POST \
  -H "X-Mcp-Key: $MCP_KEY" \
  -H "Content-Type: application/json" \
  -d '{}' \
  "$MCP_URL/call/agentiz.overview"
```

Успешный ответ обернут в объект:

```json
{
  "tool": "agentiz.overview",
  "result": {}
}
```

Пример с параметрами:

```bash
curl -sS -X POST \
  -H "X-Mcp-Key: $MCP_KEY" \
  -H "Content-Type: application/json" \
  -d '{"projectId":"<project-id>","status":"pending","limit":20}' \
  "$MCP_URL/call/agentiz.tasks"
```

### 4. Изучить объект перед изменением

Группа `agentiz-actions` меняет состояние. Сначала вызовите соответствующий read-only инструмент,
сохраните идентификатор и текущие значения, затем передавайте минимальное изменение. Удаление
business-record или воркера требует `"confirm": true`.

Для `PipelineSpec.spec` сначала обязательно запросите фактическую схему и доступные ключи ролей:

```bash
curl -sS -X POST \
  -H "X-Mcp-Key: $MCP_KEY" \
  -H "Content-Type: application/json" \
  -d '{"projectId":"<project-id>"}' \
  "$MCP_URL/call/agentiz.pipelineSpecSchema"
```

Поле `spec` передается как JSON-объект, а не строка с JSON.

## Текущий каталог

Каталог ниже проверен по коду и production endpoint 9 августа 2026 года. Источником истины во
время работы остается `GET /mcp`.

### `agentiz`: чтение и диагностика

| Инструмент | Назначение |
| --- | --- |
| `agentiz.overview` | Сводка по серверу, проектам, задачам и активным запускам |
| `agentiz.projects` | Проекты без секретов |
| `agentiz.tasks` | Краткий список задач с фильтрами |
| `agentiz.runs` | Краткий список pipeline runs с фильтрами |
| `agentiz.runDetails` | Стадии и ограниченный набор логов одного запуска |
| `agentiz.configuration` | Роли и pipeline specs проекта |
| `agentiz.pipelineSpecSchema` | Схема, дополнительные правила и примеры `PipelineSpec.spec` |
| `agentiz.workers` | Состояние и доступность воркеров без токенов |
| `agentiz.workerDetails` | Один воркер и его недавние jobs |
| `agentiz.jobs` | Состояние очереди и leases без содержимого snapshot |

### `agentiz-actions`: изменение состояния

| Инструмент | Назначение |
| --- | --- |
| `agentiz.sync` | Синхронизация одного или всех активных проектов |
| `agentiz.runTask` | Создание run и постановка задачи в очередь |
| `agentiz.cancelRun` | Отмена незавершенного run |
| `agentiz.manage` | Управляемый CRUD проектов, ролей, specs, task sources, задач и комментариев |
| `agentiz.manageWorker` | Создание и администрирование внешних воркеров |

### `general`: инфраструктура

| Инструмент | Доступ | Назначение |
| --- | --- | --- |
| `health` | public | Uptime, память и время процесса |
| `adminizer.user` | protected | CRUD пользователей Adminizer и членство в группах |
| `system.listApps` | protected | Загруженные приложения и их runtime-состояние |
| `system.toggleApp` | protected | Включение или выключение приложения |

`system.toggleApp` меняет runtime-состояние процесса и может отключить зависимость Agentiz. Перед
его вызовом проверьте `system.listApps` и граф `appDependencies`.

## Ошибки и диагностика

| HTTP status | Причина |
| --- | --- |
| `200` | Успешный каталог или вызов |
| `401` | Защищенный инструмент вызван без правильного ключа |
| `404` | Неизвестная группа или имя инструмента |
| `500` | `handler` отклонил параметры или завершился ошибкой |

Сейчас framework не применяет `inputSchema` к входному телу автоматически. Поэтому даже ошибка
параметров из `handler` возвращается как `500`, а не `400`. Читайте поле `error` и сверяйте тело с
актуальной схемой группы.

Если `/mcp` возвращает обычный `404`, проверьте по порядку:

1. `MCP_ENABLED` имеет значение `true`, а не `1` или `yes`.
2. `app-mcp` присутствует в `INIT_APPS_TO_ENABLE`.
3. Процесс был перезапущен после изменения env.
4. В логе есть `[AppMCP] ready` и endpoint `/mcp`.

Если виден только `health`, проверьте серверную переменную `MCP_ADMIN_KEY` и клиентский заголовок.
Если новый инструмент не виден, проверьте, что он добавлен в коллекцию `mcpTools`, приложение с
этой коллекцией включено, а имя инструмента уникально.

## Вызов из Adminizer Assistant

Администраторский AI Assistant использует внутренний bridge `list_mcp_tools` → `call_mcp_tool` и
вызывает тот же registry внутри процесса без HTTP. Обычным пользователям этот bridge не
предоставляется; их Adminizer skills отдельно проверяют model permissions.

Внутренний вызов не проходит HTTP-проверку `X-Mcp-Key`: авторизацию обязан выполнить сам вызывающий
bridge. Поэтому новый in-process consumer нельзя подключать напрямую к `callTool` без собственной
проверки прав.
